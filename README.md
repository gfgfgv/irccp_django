# IRCCP — International Research Center of Civil Protection (Django)

Django-версия сайта, перенесённая с React/Vite. Полноценный сервер-рендеринг
на шаблонах Django, реальная база данных SQLite, регистрация/вход через
Django auth, загрузка файлов (аватар, PDF публикаций) на сервер.

## Что внутри

- **core/models.py** — `Researcher` (профиль поверх стандартного `User`),
  `Publication`, `NewsItem`
- **core/forms.py** — регистрация (email как логин), форма загрузки публикации
- **core/views.py** — все страницы: Home, Publications, Researchers,
  Resources, Journals, Login, Register, Upload
- **core/data.py** — статический справочник Resources / Journals (как и в
  оригинале — это не пользовательский контент, поэтому не в БД)
- **templates/** — шаблоны Django (base.html + core/*.html)
- **static/css/style.css** — вручную переписанная дизайн-система оригинала
  (тёмно-синий #0D2340 / золотой #B8841E), без Tailwind
- Бейджи исследователей (Researcher / Senior Researcher / Member of
  Scientific Committee) считаются на лету по количеству публикаций — логика
  перенесена в `core/models.py::get_badge`

## Запуск локально

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

python manage.py migrate
python manage.py seed_news      # заполнить демо-новости (безопасно перезапускать)
python manage.py seed_logos     # загрузить присланные логотипы (безопасно перезапускать)
python manage.py createsuperuser  # для входа в /admin/

python manage.py runserver
```

Сайт откроется на http://127.0.0.1:8000/, админка — на http://127.0.0.1:8000/admin/.

## Деплой (чтобы сайт увидел кто угодно, бесплатно)

Рекомендую **Render.com** — бесплатно, ничего не нужно вводить в консоли,
всё делается кликами в браузере, привязывается к GitHub-репозиторию.
Проект уже подготовлен: есть `requirements.txt` с `gunicorn`/`whitenoise`,
`build.sh` и env-переменные для прод-настроек (`SECRET_KEY`, `DEBUG`,
`ALLOWED_HOSTS`, `DATABASE_URL`) — менять код не нужно.

### Шаг 1 — залей проект на GitHub

1. Зайди на https://github.com → **New repository** → назови как хочешь
   (например `irccp-django`) → **Create repository** (не добавляй README/
   .gitignore, они уже есть в проекте)
2. В PyCharm: **Git → GitHub → Share Project on GitHub** (или через
   встроенный терминал):
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/ТВОЙ_ЛОГИН/irccp-django.git
   git push -u origin main
   ```
   PyCharm может попросить залогиниться в GitHub — просто следуй подсказкам.

### Шаг 2 — создай сервис на Render

1. Зарегистрируйся на https://render.com (можно через GitHub-аккаунт —
   тогда шаг привязки репозитория пройдёт сам)
2. **New + → Web Service**
3. Выбери свой репозиторий `irccp-django`
4. Заполни поля:
   - **Name:** `irccp` (или как хочешь — это станет частью адреса)
   - **Runtime:** Python 3
   - **Build Command:** `./build.sh`
   - **Start Command:** `gunicorn irccp.wsgi`
   - **Instance Type:** Free
5. Ниже, в **Environment Variables**, добавь:
   | Key | Value |
   |---|---|
   | `SECRET_KEY` | любая длинная случайная строка (например, сгенерируй на https://djecrety.ir) |
   | `DEBUG` | `False` |
   | `PYTHON_VERSION` | `3.12.0` |
6. **Create Web Service** — Render сам соберёт и запустит проект (первый
   деплой занимает пару минут). Готовую ссылку вида
   `https://irccp.onrender.com` увидишь наверху страницы сервиса —
   её можно отправлять кому угодно.

### Важные ограничения бесплатного тарифа Render (проверено на актуальном тарифе)

- **Сайт "засыпает"** после 15 минут без посещений. Следующий человек,
  который зайдёт, будет ждать ~30-60 секунд, пока сервис "проснётся" — это
  нормально для бесплатного тарифа, не баг.
- **Файловая система эфемерна** — то есть `db.sqlite3` и все загруженные
  файлы (аватарки, PDF публикаций, логотипы) **сбрасываются** при каждом
  редеплое/рестарте/пробуждении из "сна". Для простого демо это не страшно
  (сайт всё равно откроется с теми логотипами и новостями, что были
  зашиты в момент последнего деплоя через `build.sh`), но **регистрации
  и публикации, которые сделают посетители, могут пропасть** при следующем
  пробуждении сервиса.

**Если хочешь, чтобы регистрации/публикации не терялись** — подключи
бесплатную Postgres-базу Render (данные там не привязаны к диску сервиса):

1. **New + → PostgreSQL** → Free → создать
2. Скопируй **Internal Database URL** из страницы созданной базы
3. Зайди в свой Web Service → **Environment** → добавь переменную
   `DATABASE_URL` = (вставленная ссылка) → **Save Changes** (Render сам
   передеплоит сервис)

Это решит проблему для пользователей/публикаций/новостей (они хранятся в
БД), но **загруженные файлы** (аватарки, PDF, логотипы) всё равно будут
сбрасываться — они лежат на диске, а не в БД. Бесплатная Postgres на
Render имеет свой нюанс: она перестаёт быть бесплатной через 30 дней
(нужно будет создать новую или перейти на платный тариф) — детали могут
измениться, проверяй актуальные условия на странице Render перед
запуском.

**Если для тебя принципиально, чтобы загруженные файлы не терялись** —
вариант посложнее: подключить бесплатное S3-совместимое хранилище
(например Cloudflare R2) через `django-storages`. Это отдельная,
более объёмная настройка — скажи, если понадобится, помогу настроить.

## Логотипы (категории + главный щит IRCCP)

Логотипы хранятся в базе через модели `CategoryLogo` (по одному на
категорию — Fire Safety, CBRN, EOD, Disaster Medicine, Environmental
Safety) и `SiteBranding` (главный логотип-щит IRCCP), редактируются в
**/admin/** без доступа к коду.

- Главный логотип используется в шапке сайта (навбар) и в Hero-блоке на
  главной странице.
- Логотипы категорий используются везде, где раньше были иконки категорий:
  карточки категорий на Home, фильтры на страницах Publications /
  Researchers / Resources / Journals, чипы категорий на карточках
  публикаций/ресурсов/журналов/новостей.
- Если логотип для категории (или главный логотип) ещё не загружен —
  автоматически показывается встроенная простая SVG-иконка, ничего не
  ломается.

**В этой сборке логотипы уже загружены** (из присланных файлов) — сразу
после `python manage.py migrate` дополнительно выполни:

```bash
python manage.py seed_logos
```

Эта команда подхватывает файлы из `core/default_logos/` и создаёт записи
`CategoryLogo`/`SiteBranding`. Команда безопасна для повторного запуска —
она не трогает логотипы, которые ты уже поменял через `/admin/`. Если
захочешь откатить к дефолтным картинкам принудительно:

```bash
python manage.py seed_logos --force
```

**Поменять логотип позже:** зайди в `/admin/` → `Core` → `Category logos`
или `Site logo` → загрузи новый файл. Изменения применяются сразу
(кэш логотипов сбрасывается автоматически при сохранении).

## Автообновление новостей из RSS

Сайт умеет сам подтягивать реальные новости из RSS-лент международных
организаций (ReliefWeb, IAEA, UNEP, FEMA) и раскладывать их по категориям
IRCCP — вручную ничего добавлять не нужно.

**Как это работает:**

- `core/rss_config.py` — список RSS-фидов и то, к какой категории они по
  умолчанию относятся. Плюс список ключевых слов (`CATEGORY_KEYWORDS`),
  которые могут переопределить категорию для конкретной новости (например,
  новость про "landmine" из общего фида ReliefWeb уйдёт в EOD, а не в
  Disaster Medicine).
- `core/management/commands/fetch_news.py` — команда, которая реально
  скачивает фиды, чистит HTML из описаний, определяет категорию и создаёт
  `NewsItem`. Повторный запуск не создаёт дублей (проверка по ссылке на
  оригинал, `source_url`).
- `core/scheduler.py` + `core/apps.py` — при старте `runserver` в фоновом
  потоке поднимается APScheduler, который запускает `fetch_news`
  **сразу при старте** и затем **каждые 6 часов** (настраивается через
  `RSS_FETCH_INTERVAL_HOURS` в `settings.py`).

**Запустить вручную** (без ожидания расписания):

```bash
python manage.py fetch_news
```

**Отключить автообновление** (например, чтобы новости появлялись только
через `/admin/` или командой вручную): в `irccp/settings.py` поставить
`RSS_AUTO_FETCH = False`.

**Добавить свой источник:** просто допиши словарь `{"name", "url",
"category"}` в список `RSS_FEEDS` в `core/rss_config.py` — не нужно трогать
код команды.

**Ограничение по EOD:** на момент сборки не нашлось надёжного публичного
RSS-фида именно про разминирование/EOD (GICHD и подобные организации его не
публикуют), поэтому эта категория пополняется только через ключевые слова
из общих фидов (`landmine`, `demining`, `explosive ordnance`...) — либо
добавь свой источник в `rss_config.py`.

**Важно про продакшн:** текущая реализация — фоновый поток внутри одного
процесса `runserver`, это специально сделано просто для локальной
разработки. Если позже перейдёшь на прод с несколькими воркерами
(gunicorn -w 4 и т.п.) или несколькими серверами — планировщик запустится
в каждом воркере отдельно и будет дублировать работу. На проде для этого
обычно используют cron (`* */6 * * * cd /path && python manage.py
fetch_news`) или Celery beat вместо APScheduler в процессе.

## Отличия от оригинального React-прототипа

- Вместо localStorage/sessionStorage — реальная БД SQLite и сессии Django.
- Вместо React-модалок для логина/регистрации/загрузки — отдельные страницы
  Django (проще для server-side подхода, тот же UX через редиректы + flash-сообщения).
- Пароли теперь хранятся хэшированными через стандартный Django auth,
  а не в открытом виде, как в моковых данных исходника.
- Иконки лукайд (lucide-react) заменены на небольшой набор простых
  inline-SVG в `core/templatetags/core_extras.py` — не идентичны один в один,
  но передают тот же смысл.
- Файл публикации (PDF) — необязательное дополнение к DOI-ссылке, сохраняется
  в `media/publications/`.
